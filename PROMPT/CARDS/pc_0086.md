  - Reason codes are no longer free-form strings; the registry now fail-closes unknown or decision-incompatible codes before persistence.
- Added the durable control-store migration in `db/migrations/phase03_0002_principal_context_authorization_decision.sql`.
  - The migration creates `control_access.principal_context_register` and `control_access.authorization_decision_register`.
  - It freezes tenant scoping, service-principal restrictions, authority-link lineage pairing, governance hash pairing, hot-path indexes, and row-level security in the storage contract rather than leaving those guarantees to application code alone.
- Added the implementation note/reference document in `docs/access/principal_context_and_authorization_decision_models.md`.
- Chose durable persistence rather than transient-only mirrors.
  - `PrincipalContext` and `AuthorizationDecision` are both stored as replay-safe frozen control objects so command admission, authority operations, revocation, masking, and governance simulation can reconstruct the exact authorization basis later.
- Canonical normalization now closes the hash-drift gap.
  - Scope arrays use the fixed corpus order.
  - Set-like arrays are trimmed, NFC-normalized, deduplicated, and lexicographically sorted before hashing or persistence.
  - `PrincipalContext.access_binding_hash` includes `authorization_evaluated_at` so two distinct frozen evaluations of the same session/scope facts at different times do not collide.
  - `AuthorizationDecision.access_binding_hash` is derived from the final decision posture plus the frozen principal-context binding hash and any governance basis hashes.
- `PrincipalContextBuilder` now owns translation from durable session facts into a governed principal context.
  - It resolves policy snapshot/capability sets from the compiled access matrix.
  - It preserves the full `effective_role_set[]` even when some roles have no compiled template yet.
  - It rejects revoked, expired, or device-invalidated sessions and enforces chronology monotonicity against the session issuance/step-up timeline.
  - It fail-closes service-principal human-capability leakage, empty client scope on client-acting delegation bases, and missing authority-link snapshot lineage.
- `AuthorizationDecision` normalization and factory logic now enforce the corpus decision postures explicitly.
  - `ALLOW_MASKED` requires masking rules.
  - `ALLOW` forbids masking rules.
  - `REQUIRE_STEP_UP` requires a non-`BASIC` authn target and the correct human-gate posture.
  - Governance mutation decisions must carry `dependency_topology_hash` and `simulation_basis_hash` together with the correct bounded-safe/approval posture.
  - Decision chronology is checked against `principal_context.authorization_evaluated_at`; a comparator bug discovered during verification was corrected so later decisions are accepted and only regressive decisions fail closed.
- Integrated with the adjacent authority-boundary work instead of forking it.
  - `AuthorizationDecision` consumes the shared `AuthorityLayerBoundaryContract` model from `pc_0087`.
  - The boundary builder was tightened with a scope-preserving generic return type so authorization-decision callers can pass `AUTHORIZATION_DECISION` boundaries without widening away the binding scope at compile time.
- Added and expanded focused coverage:
  - `tests/unit/backend_access/principal_context_builder.spec.ts`
  - `tests/unit/backend_access/authorization_decision_factory.spec.ts`
  - `tests/integration/backend_access/principal_context_authorization_decision_persistence.spec.ts`
  - The unit suite now covers deterministic canonicalization, service-principal restrictions, empty client scope on delegated access, missing authority-link snapshot refs, revoked-session rejection, masking posture invariants, governance hash pairing, monotonic chronology, `REQUIRE_STEP_UP` authn constraints, and reason-code catalog enforcement.
- Assumption recorded:
  - `config/access/access_control_matrix.json` currently omits a top-level `contract_version`; `PolicySnapshotRefResolver` accepts the omission but still fail-closes if a conflicting version is present.
