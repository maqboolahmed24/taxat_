## Implementation Notes

- Implemented the governed runtime binding substrate under `packages/backend-access`:
  - `src/models/scope_execution_binding.ts`
  - `src/repositories/scope_execution_binding_repository.ts`
  - `src/services/validate_effective_scope_binding.ts`
  - `src/services/materialize_scope_execution_binding.ts`
  - `src/services/masking_projection_context_builder.ts`
  - `src/services/enforce_access_scope_and_masking.ts`
  - `src/services/runtime_scope_guard.ts`
  - `src/index.ts`
- Added `config/access/runtime_scope_failure_codes.json`.
  - The runtime bridge now emits one governed failure family instead of letting handlers invent per-route execution-binding errors.
  - The catalog covers empty runtime scope, widening beyond request or frozen effective scope, analysis-mode live scope, masking posture mismatch, atomic live-request narrowing, partition widening, stale replay, missing bindings, and service-principal reuse of client-acting bindings.
- Added `docs/access/scope_execution_binding_and_runtime_enforcement.md`.
  - The document makes the adoption rule explicit: once a frozen execution binding exists, downstream code should branch from `runtime_scope[]`, `scope_execution_binding`, and `masking_context`, never from raw `requested_scope[]`.
- Closed the generated-binding gap by wrapping the generated `ScopeExecutionBinding` type with a stricter local model.
  - The generated schema binding exposes `requested_scope` and `executable_scope` as generic JSON values.
  - `scope_execution_binding.ts` now reasserts those fields as canonical string scope vectors and enforces the schema-level invariants in one place instead of letting callers cast ad hoc.
- Added shared scope-family and access-binding helpers to `principal_context_normalizer.ts`.
  - The runtime layer now derives explicit `requested_scope_family` / `executable_scope_family`, computes mutation atomicity from the requested scope family, and hashes frozen execution bindings from the source authorization-decision binding plus executable runtime facts.
  - That binding hash design preserves replay invalidation after session-binding rotation and step-up completion instead of letting a pre-step-up binding masquerade as the same access posture.
- `validate_effective_scope_binding.ts` is the fail-closed structural validator for runtime execution.
  - It proves runtime scope is non-empty, remains within requested scope and frozen effective scope, respects analysis-mode read-only posture, preserves masking posture, enforces atomic live-request behavior, and prevents partition widening.
  - It returns structured `VALID` / `INVALID` results with governed reason codes rather than relying on assertion crashes.
- `materialize_scope_execution_binding.ts` freezes one authoritative binding from a frozen `AuthorizationDecision` and `PrincipalContext`.
  - The service preserves requested vs executable scope, executable partition coverage, reduction posture, mutation atomicity, required approvals, required authn level, masking rules, and reason-code lineage.
  - It persists reusable bindings through the shared repository when requested.
- `enforce_access_scope_and_masking.ts` is the downstream execution API.
  - It returns `runtime_scope[]`, `masking_context`, and the frozen `scope_execution_binding` together so handlers do not re-derive executable semantics locally.
- `masking_projection_context_builder.ts` closes the projection-leak gap.
  - The masking context is explicitly `PROJECTION_ONLY`, applies to human-facing API/export/read-model surfaces, and explicitly does not apply to canonical facts, compute, authority packets, or request hashing.
- Chose to add a shared `ScopeExecutionBindingRepository` now, not only later manifest embedding.
  - `RunManifest` and `AuthorityOperation` will eventually embed the same binding payload.
  - This card still needs a durable store today because command-admission and replay verification already need a frozen binding substrate before those manifest and authority-operation models arrive.
  - The repository stores the governed binding plus source authorization/principal-context binding hashes, tenant/session/principal metadata, delegation basis, and action metadata for replay-safe checks.
- `runtime_scope_guard.ts` now owns replay/reuse checks on stored bindings.
  - It rejects stale access binding reuse after step-up rotation, widened replay partitions, widened replay scope, analysis-mode live replay, and service-principal reuse of client-acting bindings.
  - The default `RuntimeScopeGuard.enforce(...)` path now wires repository-backed persistence correctly, so `persist: true` through the main facade actually records the frozen binding.
- Added focused coverage:
  - `tests/unit/backend_access/scope_execution_binding.spec.ts`
  - `tests/integration/backend_access/runtime_scope_enforcement.spec.ts`
  - The new tests cover empty-scope failure, analysis-mode live-scope rejection, masking posture mismatch, atomic live-request narrowing, projection-only masking, partition widening on replay, service-principal replay misuse, schema-valid binding materialization, durable storage, replay success on matching context, and replay invalidation after step-up rotation.
